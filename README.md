# ระบบตรวจสอบใบลงเวลา (Check Salary)

เว็บสำหรับให้พนักงานเข้ามาตรวจสอบใบลงเวลาของตัวเอง แล้วกด **ยืนยัน** หรือ **แจ้งแก้ไข**

ระบบแบ่งเป็น 2 ส่วน:

| ส่วน | อยู่ที่ไหน | ไฟล์ |
|---|---|---|
| **หน้าเว็บ** (HTML) | GitHub Pages (repo นี้) | `index.html`, `config.js`, `assets/` |
| **ระบบเบื้องหลัง** (API) | Google Apps Script | `apps-script/Code.gs` (ไฟล์เดียว) |
| **ฐานข้อมูล** | Google Sheet + Google Drive ของคุณ | ระบบสร้างให้อัตโนมัติ |

> **ทำไมต้องมี Apps Script?** หน้าเว็บบน GitHub เป็นไฟล์ที่ใครก็เปิดดูโค้ดได้ ถ้าให้หน้าเว็บต่อ Google Sheet ตรงๆ
> ทุกคนจะเห็นและแก้ข้อมูลของพนักงานทุกคนได้ Apps Script จึงเป็นคนกลางที่ตรวจสอบสิทธิ์ก่อนทุกครั้ง
> และข้อมูลจะไม่ถูกเก็บไว้ใน GitHub

## วิธีติดตั้ง (ประมาณ 10 นาที ไม่ต้องสร้างไฟล์เอง)

### ส่วนที่ 1: ตั้งค่า Google Apps Script (คัดลอก 1 ไฟล์)

1. เปิดไฟล์ [`apps-script/Code.gs`](apps-script/Code.gs) ใน GitHub แล้วกดปุ่ม **Copy raw file** (ไอคอนรูปกระดาษสองแผ่นด้านขวาบนของไฟล์)
2. ไปที่ <https://script.google.com> แล้วกด **โปรเจกต์ใหม่ (New project)** จากนั้นตั้งชื่อ เช่น `ระบบตรวจสอบใบลงเวลา`
3. ในไฟล์ `Code.gs` ให้**ลบโค้ดเดิมทั้งหมด** แล้ว**วาง**โค้ดที่คัดลอกมา จากนั้นกด **บันทึก** (Ctrl+S)
4. ที่แถบด้านบน เลือกฟังก์ชัน **`setup`** แล้วกด **เรียกใช้ (Run)**
   - Google จะขอสิทธิ์ ให้กด **ตรวจสอบสิทธิ์** แล้วเลือกบัญชีของคุณ
   - ถ้ามีหน้าเตือน "Google ยังไม่ได้ยืนยันแอปนี้" ให้กด **ขั้นสูง (Advanced)** แล้วกด **ไปที่ ... (ไม่ปลอดภัย)** ซึ่งเป็นเรื่องปกติของสคริปต์ที่สร้างเอง
   - เมื่อเสร็จแล้ว **บันทึกการดำเนินการ (Execution log)** จะแสดงลิงก์ของ Google Sheet และโฟลเดอร์ Drive ที่ระบบสร้างให้
5. กด **การทำให้ใช้งานได้ (Deploy)** แล้วเลือก **การทำให้ใช้งานได้รายการใหม่ (New deployment)**
   - กดเฟืองข้าง "เลือกประเภท" แล้วเลือก **เว็บแอป (Web app)**
   - **เรียกใช้ในฐานะ (Execute as): ฉัน (Me)**
   - **ผู้ที่มีสิทธิ์เข้าถึง (Who has access): ทุกคน (Anyone)**
   - กด **Deploy** แล้ว**คัดลอก URL ของเว็บแอป** ซึ่งลงท้ายด้วย `/exec`
6. (ทางเลือก) วาง URL นั้นในเบราว์เซอร์ ถ้าขึ้นข้อความ `"API พร้อมใช้งาน"` แปลว่าส่วนนี้เสร็จแล้ว

### ส่วนที่ 2: ตั้งค่าหน้าเว็บบน GitHub (แก้ 1 ไฟล์)

1. ใน repo นี้ เปิดไฟล์ [`config.js`](config.js) แล้วกดไอคอน **ดินสอ ✏️ (Edit this file)**
2. แทนที่ข้อความ `วาง_URL_ของ_Apps_Script_ที่นี่` ด้วย URL ที่คัดลอกมา (ต้องอยู่ระหว่างเครื่องหมาย `' '`) ตัวอย่างเช่น
   ```js
   API_URL: 'https://script.google.com/macros/s/AKfycbx.../exec',
   ```
3. กด **Commit changes...** แล้วกด **Commit changes** อีกครั้ง
4. ไปที่ **Settings** (แท็บด้านบนของ repo) แล้วเลือก **Pages** ที่เมนูซ้าย
   - **Source:** `Deploy from a branch`
   - **Branch:** เลือก branch ที่มีไฟล์ `index.html` และโฟลเดอร์ `/ (root)` แล้วกด **Save**
5. รอ 1–2 นาที แล้วรีเฟรชหน้านั้น ด้านบนจะแสดงลิงก์เว็บของคุณ ในรูปแบบ `https://<ชื่อผู้ใช้ GitHub>.github.io/Check-salary/`

### ส่วนที่ 3: เปิดปุ่ม "ลงชื่อเข้าใช้ด้วย Google" (แนะนำ ทำครั้งเดียว ฟรี)

พนักงานกดปุ่มเดียวแล้วเลือกบัญชี Google ก็เข้าระบบได้ ไม่ต้องกรอกอีเมลหรือรหัส
ก่อนใช้ต้องสร้าง **Client ID** จาก Google Cloud ก่อน (ถ้ายังไม่ทำส่วนนี้ ระบบจะใช้การล็อกอินด้วยรหัสทางอีเมลแทน)

**3.1 สร้าง Client ID ใน Google Cloud**
1. ไปที่ <https://console.cloud.google.com> แล้วล็อกอินด้วยบัญชีเดียวกับที่สร้าง Apps Script
2. กดช่องเลือกโปรเจกต์ด้านบน แล้วกด **โปรเจกต์ใหม่ (New project)** ตั้งชื่อ เช่น `check-salary` แล้วกด **สร้าง**
3. เลือกโปรเจกต์นั้น จากนั้นที่เมนู ☰ ไปที่ **APIs และบริการ → หน้าจอขอความยินยอม OAuth (OAuth consent screen)** แล้วกด **เริ่มต้นใช้งาน (Get started)**
   - **ชื่อแอป:** `ระบบตรวจสอบใบลงเวลา`
   - **อีเมลสนับสนุนผู้ใช้:** อีเมลของคุณ
   - **กลุ่มเป้าหมาย (Audience):** เลือก **ภายนอก (External)**
   - **ข้อมูลติดต่อ:** อีเมลของคุณ ติ๊กยอมรับ แล้วกด **สร้าง**
4. ไปที่เมนู **กลุ่มเป้าหมาย (Audience)** แล้วกด **เผยแพร่แอป (Publish app)** → **ยืนยัน**
   ถ้าไม่เผยแพร่ จะมีแค่คนที่อยู่ในรายชื่อทดสอบที่ล็อกอินได้ แอปนี้ขอแค่ชื่อและอีเมล จึง**ไม่ต้องรอ Google ตรวจสอบ**
5. ไปที่เมนู **ไคลเอ็นต์ (Clients)** แล้วกด **+ สร้างไคลเอ็นต์ (Create client)**
   - **ประเภทแอปพลิเคชัน:** `เว็บแอปพลิเคชัน (Web application)`
   - **ต้นทาง JavaScript ที่ได้รับอนุญาต (Authorized JavaScript origins):** กด **เพิ่ม URI** แล้วใส่ `https://<ชื่อผู้ใช้ GitHub>.github.io`
     (ไม่ต้องใส่ `/Check-salary` และไม่ต้องมี `/` ปิดท้าย)
   - กด **สร้าง** แล้ว**คัดลอก Client ID** ซึ่งลงท้ายด้วย `.apps.googleusercontent.com`

**3.2 ใส่ Client ID 2 ที่**
1. **ใน GitHub:** แก้ไฟล์ [`config.js`](config.js) โดยแทนที่ `วาง_Client_ID_ที่นี่` ด้วย Client ID แล้วกด Commit
2. **ใน Apps Script:** กดเฟือง **การตั้งค่าโปรเจกต์ (Project Settings)** แล้วเลื่อนลงไปที่ **คุณสมบัติของสคริปต์ (Script Properties)**
   กด **เพิ่มคุณสมบัติของสคริปต์** แล้วกรอก
   - **คุณสมบัติ (Property):** `GOOGLE_CLIENT_ID`
   - **ค่า (Value):** Client ID เดียวกัน

   จากนั้นกด **บันทึก**

> ระบบหลังบ้านใช้ Client ID ตัวนี้ตรวจว่าการล็อกอินมาจากเว็บของคุณจริง Client ID ไม่ใช่ข้อมูลลับ จึงใส่ใน GitHub ได้

### ส่วนที่ 4: เริ่มใช้งาน
1. เปิดลิงก์เว็บแล้วกด **ลงชื่อเข้าใช้ด้วย Google** ด้วยบัญชีที่สร้าง Apps Script ระบบจะเข้า**หน้าผู้ดูแล**ให้อัตโนมัติ
2. ไปที่แท็บ **จัดการพนักงาน** แล้วเพิ่มรหัส ชื่อ และ**อีเมลบัญชี Google (Gmail)** ของพนักงาน ซึ่งต้องตรงกับบัญชีที่พนักงานใช้กดล็อกอิน
3. ไปที่แท็บ **อัปโหลดใบลงเวลา** เลือกเดือน แล้วแนบไฟล์ (ดูหัวข้อ "การอัปโหลดไฟล์ PDF รวม" ด้านล่าง)
4. ส่งลิงก์เดียวกันให้พนักงาน พนักงานกดปุ่ม Google แล้วจะเห็นเฉพาะใบลงเวลาของตัวเอง คนที่ไม่มีบัญชี Google กดลิงก์ **"เข้าสู่ระบบด้วยรหัสทางอีเมล"** ได้

## การอัปโหลดไฟล์ PDF รวม (หลายคนในไฟล์เดียว)

ถ้าโปรแกรมลงเวลาส่งออกมาเป็น PDF ไฟล์เดียวที่รวมทุกคน ให้ใช้โหมด **"PDF รวมหลายคน (แยกให้อัตโนมัติ)"** ซึ่งเป็นโหมดเริ่มต้นของแท็บอัปโหลด

1. เลือกเดือน แล้วลากไฟล์ PDF รวมมาวาง
2. ระบบอ่านข้อความทีละหน้า แล้วหา **รหัสพนักงาน** หรือ **ชื่อ-นามสกุล** ที่ตรงกับรายชื่อในแท็บจัดการพนักงาน
   - ไม่ต้องสนใจคำนำหน้าชื่อ (นาย/นาง/นางสาว) และช่องว่าง ระบบจัดการให้
   - **หน้าที่ไม่พบชื่อ** จะถือเป็นหน้าต่อของคนก่อนหน้า (กรณี 1 คนมีหลายหน้า)
   - หน้าแรกที่ไม่มีชื่อใคร เช่น หน้าปกหรือหน้าสรุป จะขึ้นกรอบสีแดงให้เลือก **"ไม่ใช้หน้านี้"**
3. ตรวจภาพย่อของแต่ละหน้า (คลิกเพื่อดูภาพใหญ่) ถ้าหน้าไหนผิดคน เปลี่ยนได้ที่ช่องเลือก
4. กด **"แยกไฟล์และอัปโหลด"** ระบบจะสร้าง PDF แยกของแต่ละคนแล้วอัปโหลดให้ทีละคน

> **ถ้าเป็น PDF ที่สแกนจากกระดาษ** ระบบจะอ่านชื่อไม่ได้ ให้เลือกพนักงานที่ **หน้าแรกของแต่ละคน** แล้วหน้าถัดไปจะเป็นของคนเดียวกันอัตโนมัติจนกว่าจะเจอหน้าที่เลือกคนใหม่
>
> **เคล็ดลับ:** ใส่รหัสพนักงานในแท็บจัดการพนักงานให้ **ตรงกับรหัสในโปรแกรมลงเวลา** จะแยกได้แม่นที่สุด

## การแก้ไขในภายหลัง
- **แก้หน้าเว็บ** (`index.html`, `assets/`): แก้ใน GitHub แล้ว Commit เว็บจะอัปเดตเองภายในไม่กี่นาที
- **แก้โค้ด Apps Script** (`apps-script/Code.gs`): วางโค้ดใหม่ใน Apps Script แล้ว **Run `setup` อีกครั้ง** (เผื่อมีการขอสิทธิ์ใหม่) จากนั้นไปที่ **Deploy → จัดการการทำให้ใช้งานได้ (Manage deployments)** กดดินสอแก้ไข เลือก **เวอร์ชัน: เวอร์ชันใหม่** แล้วกด Deploy วิธีนี้ทำให้ **URL เดิมยังใช้ได้** และไม่ต้องแก้ `config.js`
  - ⚠️ ถ้ากด "New deployment" จะได้ URL ใหม่ และต้องแก้ `config.js` ตาม

## ความสามารถ

### ผู้ดูแลระบบ
- **ภาพรวมรายเดือน** แสดงว่าใครยังไม่ได้อัปโหลด ใครยังไม่เปิดดู ใครเปิดดูแล้ว ใครขอแก้ไข และใครยืนยันแล้ว พร้อมเวลาที่ยืนยัน
- **คำขอแก้ไขที่รอตอบ** จากทุกเดือน
- **แยก PDF รวมหลายคน** เป็นไฟล์ของแต่ละคนให้อัตโนมัติ หรือ**อัปโหลดไฟล์แยกรายคน**หลายไฟล์พร้อมกัน (PDF / JPG / PNG ไม่เกิน 10 MB ต่อไฟล์)
- **ตอบกลับคำขอแก้ไข** และ **อัปโหลดฉบับแก้ไข** โดยฉบับเดิมจะถูกเก็บเป็นประวัติ ส่วนฉบับใหม่พนักงานต้องยืนยันอีกครั้ง
- **จัดการพนักงาน**: เพิ่ม แก้ไข และลบได้ ถ้าลบ พนักงานจะล็อกอินไม่ได้ทันทีแต่ประวัติยังอยู่
- **ประวัติกิจกรรม** ของแต่ละใบลงเวลา

### พนักงาน
- ล็อกอินด้วยปุ่ม **ลงชื่อเข้าใช้ด้วย Google** หรือใช้อีเมลรับ **รหัส 6 หลัก** สำหรับคนที่ไม่มีบัญชี Google
- ดูและดาวน์โหลดใบลงเวลาของตัวเองได้ ใช้งานบนมือถือได้
- **ยืนยันว่าถูกต้อง** ได้หลังเปิดดูไฟล์ เมื่อยืนยันแล้วจะล็อกและแก้ไขไม่ได้
- **แจ้งแก้ไขเวลา** โดยพิมพ์รายละเอียดแล้วคุยต่อกับผู้ดูแลได้

### หลักฐานการยืนยัน (บันทึกในชีต `ใบลงเวลา`)
- **เวลาที่ยืนยัน** ซึ่งเป็นเวลาของเซิร์ฟเวอร์ Google พนักงานจึงแก้เวลาจากเครื่องตัวเองไม่ได้
- **รายละเอียดการยืนยัน** ได้แก่ อีเมล เวลา ฉบับที่ อุปกรณ์ และ **SHA-256 ของไฟล์** ซึ่งพิสูจน์ได้ว่ายืนยันไฟล์ฉบับไหน
- **เวลาที่เปิดดูครั้งแรกและครั้งล่าสุด** และจำนวนครั้งที่เปิดดู
- ทุกการกระทำจะถูกบันทึกเพิ่มในชีต `บันทึกกิจกรรม` ด้วย

## โครงสร้างข้อมูลใน Google Sheet

| ชีต | เก็บอะไร |
|---|---|
| `พนักงาน` | รหัสพนักงาน ชื่อ-นามสกุล อีเมล และวันที่เพิ่ม |
| `ใบลงเวลา` | 1 แถวต่อ 1 ไฟล์ ได้แก่ รอบเดือน ฉบับที่ สถานะ ไฟล์ SHA-256 เวลาเปิดดู และเวลาที่ยืนยัน |
| `ข้อความแก้ไข` | ข้อความระหว่างพนักงานกับผู้ดูแล |
| `บันทึกกิจกรรม` | บันทึกทุกการกระทำ เช่น ล็อกอิน เปิดดู ยืนยัน อัปโหลด เพิ่มหรือลบพนักงาน |

สถานะใบลงเวลามีดังนี้ `รอตรวจสอบ` → `ขอแก้ไข` → `ยืนยันแล้ว` ส่วนฉบับเก่าที่มีฉบับใหม่มาแทนจะมีสถานะ `ถูกแทนที่`

> ⚠️ **อย่าเปลี่ยนชื่อชีต และอย่าสลับลำดับคอลัมน์** เพราะระบบอ่านข้อมูลตามตำแหน่งคอลัมน์ แนะนำให้ตั้ง **ป้องกันชีต (Protect sheet)** ไว้เพื่อกันการแก้ไขโดยไม่ตั้งใจ

## ข้อควรรู้
- **โค้ดใน repo นี้เป็นสาธารณะ** แต่ไม่มีข้อมูลลับอยู่ในโค้ด ข้อมูลพนักงานและไฟล์อยู่ใน Google Sheet และ Drive ของคุณเท่านั้น
- **โควตาอีเมล:** ใช้เฉพาะการล็อกอินด้วยรหัสทางอีเมล บัญชี Gmail ส่งได้ประมาณ **100 ฉบับต่อวัน** (ล็อกอินด้วย Google ไม่ใช้โควตานี้) เมื่อล็อกอินแล้วจะอยู่ในระบบได้ 6 ชั่วโมง
- **ความปลอดภัย:** รหัส OTP ใช้ได้ 10 นาที กรอกผิดได้ไม่เกิน 5 ครั้ง และขอรหัสใหม่ได้ทุก 1 นาที ผู้ดูแลระบบคือเจ้าของ Apps Script เพียงคนเดียว
- ปรับค่าต่างๆ ได้ที่ส่วน "ค่าตั้งต้น" ด้านบนของ `apps-script/Code.gs` เช่น ขนาดไฟล์สูงสุด หรือระยะเวลาที่อยู่ในระบบ

## ทดสอบ (สำหรับนักพัฒนา)
```bash
node tests/api.test.js
```
จำลองบริการของ Google (Sheet, Drive, Cache, Mail) แล้วรันโค้ดใน `apps-script/Code.gs` ผ่าน `doPost` เพื่อทดสอบการล็อกอิน สิทธิ์ การอัปโหลด การแจ้งแก้ไข และการยืนยัน
